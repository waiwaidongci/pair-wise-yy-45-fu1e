# 服装品牌打样开发与版型修订工作台

为服装产品开发团队提供款式档案、样品轮次、尺寸实测、部位批注、替代改版方案、审核锁定和修订历史。

## 技术栈

React + MUI + Redux Toolkit + RTK Query + React Router + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62045`。

## 核心工作流

- 从款式档案进入开发轮次，维护尺码、面辅料、色卡和工艺要求。
- 对比两轮尺寸实测，自动高亮超出容差的部位并关联试穿意见。
- 点击样衣图片部位添加批注，或由版师提交替代方案和责任人。
- 负责人采纳方案、填写未提交草稿，审核完成后锁定轮次并保留完整历史。

## 离线修订批次

版师到工厂后常离线评审，款式档案和样衣版本审核锁定后只能口头核对。离线修订批次补齐这一环节：

- **断网合并**：断网时先在本机合并尺寸实测、批注和替代方案，存入离线批次。
- **联网重算**：联网后发现正式版本已改过，按部位逐字段做三路合并（锁定快照 / 离线批次 / 正式版本）。
- **冲突保留两份**：同一部位两边都改过判为冲突，保留离线与正式两份副本等待确认，不覆盖锁定快照。
- **失败可重试**：合并失败后批次原样保留、变更不丢失，可随时重试。
- **来源标清**：款式档案、修订历史、审核状态均标注来源（正式版本 / 离线批次）。
- **锁定只进待审**：锁定版本合并后不修改原记录，仅进入待审修订队列等待确认。

在左侧导航「离线批次」中管理批次、查看逐部位字段级合并结果、确认冲突或重试失败批次。可开启「模拟联网失败」演示失败重试流程。
